# 議論形成の場 Agora: 人文系・言語文化箱庭シミュレーション Prototype v2

Gemini APIを利用して、日米の文化的背景を持つ2体のAIエージェント間で多面的な対話シミュレーションを行い、その論理構造を第三者記録係（Recorder）が定期的に分析・構造化して長期記憶として蓄積・出力するシミュレーション基盤です。

---

## 1. ファイル構成

- **`app.py`**: Webブラウザ上で直感的に操作できるGUIダッシュボード（Streamlit版、リアルタイム描画＋デモ再生モード＋Secrets/PW保護完備）
- **`visualization.py`**: Mermaidによる論点展開ツリー（フローチャート）自動生成およびHTMLレンダリングモジュール

- **`dialogue_simulation.py`**: シミュレーションのコアロジック・CLI統合プログラム

- **`DEPLOY.md`**: Streamlit Community Cloud での完全無料Web公開手順書

## 3. Gemini APIキーの設定

APIキーの指定方法は以下の通りに対応しています（コードへの直書きは不要です）。

### 方法A: Web GUI 画面上で入力する（推奨・BYOK方式）
Webアプリ（`app.py`）を起動後、サイドバーの「🔑 APIキー設定」欄にお手持ちのGemini APIキーを入力するだけで即座に利用できます。キーはブラウザセッション内でのみ一時使用され、サーバーには保存されません。
※ APIキーをお持ちでない場合も、モード選択で「🎬 発表デモ再生モード」を選ぶことで、キー不要・通信ゼロで全機能を体験できます。

### 方法B: 環境変数を設定する（ローカル開発用）
```bash
export GEMINI_API_KEY="AIzaSy..."
```

### 方法C: CLI起動時に対話入力する
CLI版の起動時に環境変数が未設定の場合、`getpass` により画面上に文字を表示させずに安全に入力できます。

## 4. APIモデル名について

### 既定モデル候補
プログラム内の `MODEL_CANDIDATES` には以下が設定されており、先頭から順に試行されます：
1. `gemini-3.1-flash-lite`
2. `gemini-3.5-flash-lite`

### モデル名の変更・設定方法
ご契約のAPIキーや利用環境で上記モデルが利用できない場合（`404 NOT_FOUND` エラー等）、コードを直接編集することなく、環境変数 `GEMINI_MODEL_CANDIDATES` で利用可能なモデルをカンマ区切りで上書き指定できます。

```bash
# 例: gemini-2.5-flash または gemini-2.0-flash を使用する場合
export GEMINI_MODEL_CANDIDATES="gemini-2.5-flash,gemini-2.0-flash"
```

利用可能なモデルの一覧は、以下のPythonワンライナーで確認できます：
```bash
python3 -c "from google import genai; client = genai.Client(); print([m.name for m in client.models.list()])"
```

## 5. 実行方法

### (1) Web GUI（Streamlit）で直感的に動かす（推奨・一番わかりやすい！）

```bash
# コマンドで起動する場合
streamlit run app.py
```
- **Macの場合**: フォルダ内の **`run_web_ui.command`**（またはプロジェクト直下の **`Agora(Web版)を起動.command`**）をダブルクリックするだけで、自動でブラウザ（http://localhost:8501）が開いて操作画面が立ち上がります。
- **Windowsの場合**: フォルダ内の **`run_web_ui.bat`**（またはプロジェクト直下の **`Agora(Web版)を起動.bat`**）をダブルクリックするだけで、自動でブラウザ（http://localhost:8501）が開いて操作画面が立ち上がります。

### (2) コンソール（CLI）で実行する場合

```bash
python dialogue_simulation.py
```
- **Macの場合**: フォルダ内の **`run_agora.command`** をダブルクリックして起動できます。
- **Windowsの場合**: フォルダ内の **`run_agora.bat`** をダブルクリックして起動できます。

実行すると以下の設定プロンプトが表示されます：
1. **対話プリセットの選択**:
   - `[1]` **功利主義 vs 義務論（カント倫理学）**: AIトリアージや自動運転の緊急アルゴリズムにおける効用計算と人間の尊厳
   - `[2]` **実証科学（客観主義） vs 現象学（身体性・生の意味論）**: AIの創作・応答に「心」や「美的価値」を認められるか
   - `[3]` **デジタル直接民主主義 vs 熟議民主主義**: 意思決定の直接反映・効率化と市民間の熟慮・少数者配慮
   - `[4]` **日米文化比較（オリジナル）**: 日米の言語・文化的視点からの教育AIレポート議論
   - `[5]` **カスタム（自由入力）**: 独自のエージェント名と役割・立場を入力して対話
2. **議題の決定**:
   - 各プリセットに応じた推奨議題が自動セットされます（空欄で Enter を押すと推奨議題がそのまま適用されます）。
3. **対話ラウンド数の入力**:
   - 空欄で Enter を押すと、既定値（10ラウンド）が適用されます。

対話の進行中、`RECORD_EVERY`（既定3ラウンド）ごとに対話がRecorderによって分析され、JSON構造化された要約が各エージェントの長期記憶に追加されます。
シミュレーションが終了すると、すべての発言、エージェント設定、分析記録が `dialogue_experiment_v2.json` に保存されます。

### (2) 単体テストの実行（APIキー不要）

APIキーを設定していないオフライン環境でも、全15件のテストで全ロジック（Persona、プリセット整合性、プロンプト生成、未記録ターン回収等）を検証可能です：

```bash
python test_dialogue_simulation.py
```

## 6. 設計・改修上の主な改善点

1. **エージェント・立場の動的指定とプリセット基盤 (`Persona` / `AgentConfig`) 【第1週成果】**:
   - ハードコードされていたエージェント設定をリファクタリングし、`Persona` クラスを通じて役割・立場、使用言語、思考・論理スタイル、前提知識を動的に注入可能にしました。
   - 授業発表・研究に直結する4つの哲学・人文・社会思想プリセットを完備。
2. **未記録ターンの完全回収 (指示書 19)**:
   - ラウンド総数が `RECORD_EVERY`（3）の倍数でない場合（例: 10ラウンド指定時、第10ラウンド）、従来は未記録のまま終了していましたが、終了時に自動で残余セグメントをRecorderへ渡し、全対話の構造化記録を漏れなく保存するようにしました。
3. **セッション分離と長期記憶の整理 (指示書 16, 17)**:
   - 各セッション開始時にエージェントおよび記憶を新設し、過去の実験結果が混ざらないよう保証しました。
   - 自側記録と相手側記録をエージェントプロンプト内で明確に区別して注入するフィルタリングを追加しました。
4. **エラーハンドリングと再試行制御 (指示書 18)**:
   - 一時的な通信エラー（`503`, `429`, `500` 等）は指数バックオフ＋ジッターで再試行。
   - 認証失敗（`401`）、不正な引数（`400`）、モデル不存在（`404`）などの回復不能なエラーは即座に検知して無限リトライを回避。
5. **関数の小型化と型ヒント・テスト容易性 (指示書 4, 20)**:
   - セッション実行部や記録処理部を小さな関数に分割し、依存性注入（DI）をサポートしてモックテストが可能なアーキテクチャにリファクタリングしました（全15テスト完備）。
